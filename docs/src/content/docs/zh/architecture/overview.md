OriginLang 自底向上分为八层，从基础设施直到应用集成层。

```
┌─────────────────────────────────────────────────────────────────────────────────────┐
│  L8 · 应用集成层                                                                    │
│  领域产品 / 企业中台 / AI 工作台 / SaaS 控制台                                        │
├─────────────────────────────────────────────────────────────────────────────────────┤
│  L7 · 平台治理层                                                                    │
│  插件市场 · OCI 注册中心 · 版本/签名/升级/回滚                                          │
├─────────────────────────────────────────────────────────────────────────────────────┤
│  L6 · 前端 UI 扩展层                                                                 │
│  Web Components + Module Federation · 菜单/路由/视图/组件/面板                          │
├─────────────────────────────────────────────────────────────────────────────────────┤
│  L5 · 插件运行时层                                                                   │
│  ① Wasm 沙箱  ② 子进程  ③ 原生 .so/.dll  ④ 远程 HTTP/TCP                               │
├─────────────────────────────────────────────────────────────────────────────────────┤
│  L4 · 多语言 SDK 层                                                                  │
│  SDK: Go | Rust | Java | Python | C++ | TypeScript                                  │
├─────────────────────────────────────────────────────────────────────────────────────┤
│  L3 · 协议与传输层                                                                    │
│  JSON-RPC 2.0 · Manifest Schema · Codec · stdio / TCP / HTTP / Wasm                 │
├─────────────────────────────────────────────────────────────────────────────────────┤
│  L2 · 内核层                                                                         │
│  插件管理器 · 扩展点注册表 · 事件总线 · 安全 · 配额 · 可观测性                            │
├─────────────────────────────────────────────────────────────────────────────────────┤
│  L1 · 基础设施层                                                                     │
│  Bazel 构建 · Wasmtime 引擎 · K8s Operator · OCI Registry · PostgreSQL / Redis      │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

## 内核实现策略

- **内核核心**：归属 `runtime/core`、`runtime/services`、`runtime/ipc` 与 `runtime/host-api`；可按子模块选择实现语言，但不能改变这组公开目录边界。
- **性能敏感子模块**：如 Wasm 桥接或资源配额执行器，应归属 `engine/` 或 `runtime/services`；有充分理由时可使用 Rust 与 FFI 边界。
- **多语言宿主适配**：归属 `sdk/` 与 `adapters/`。SDK 消费稳定运行时契约，而不反向依赖产品应用或插件。

## 各层要点

### L2 · 内核（六大子系统）

| 子系统 | 职责 | 状态 |
| --- | --- | --- |
| **插件管理器** | 加载、握手、查找、关闭；实例池、健康检查 | 规划中的运行时服务 |
| **扩展点注册表** | 贡献点模型：后端 API + 前端 UI 贡献 | 规划中的运行时服务 |
| **事件总线** | 进程内同步 Pub/Sub + 分布式异步（NATS/Redis） | 规划中的运行时服务 |
| **安全引擎** | 三层：能力清单 → 租户授权 → 用户策略 | 规划中的运行时服务 |
| **资源配额** | 令牌桶 QPS、并发、CPU 时间、内存限制 | 规划中的运行时服务 |
| **可观测性采集器** | Prometheus 指标、OpenTelemetry 追踪、结构化日志 | 规划中的运行时服务 |

### L3 · 协议与传输

协议边界为 **JSON-RPC 2.0**。`runtime/ipc` 负责消息分帧及 stdio/TCP 传输实现；HTTP、Wasm、原生和进程内传输仍是未来扩展点。目标矩阵见[传输层](transports/)页面。

### L6 · 前端 UI 扩展层

插件作者可以给任意后端插件附带一个前端 UI 扩展包。UI 扩展以 **Web Components（Custom Elements v1 + Shadow DOM）** 交付——这是跨框架标准载体——辅以 **Module Federation** 懒加载重型业务模块。宿主应用框架无关（React、Vue、Angular、Svelte 均可）。

## 与现有仓库的映射

| 层 | 位置 |
| --- | --- |
| L2 内核 | `runtime/core`、`runtime/services`、`runtime/host-api` |
| L3 协议与传输 | `runtime/ipc` |
| L4 多语言 SDK | `sdk/` 各语言 SDK |
| L4 执行引擎 | `engine/`、`adapters/`（Node.js、Python、WASM） |
| L7 治理 | `services/` 与 `apps/` 中的产品应用 |
| L1 构建 | 根 `MODULE.bazel`、各目录 `BUILD` 文件 |

仓库级职责边界见[项目结构](../getting-started/project-structure/)。
