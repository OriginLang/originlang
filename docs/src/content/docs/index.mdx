## What is OriginLang?

OriginLang is a **plugin-based, polyglot platform foundation** (底座). Any team building a product — a SaaS platform, developer tool, AI workbench, enterprise middle-platform, or desktop/mobile app — can build on OriginLang and get:

- **Polyglot plugins**: write backend logic plugins in one of six first-class languages — Go, Rust, Java, Python, C++, or TypeScript — and UI extensions with TS/JS + your favorite frontend framework.
- **Polyglot hosts**: embed the OriginLang kernel in any of the same six languages.
- **Dynamic plugin-market-grade capabilities**: runtime hot-load, hot-upgrade, hot-unload, dependency resolution, fine-grained permissions, and plugin-market distribution.
- **SaaS-native multi-tenancy**: tenant-scoped plugin visibility, quotas, metering, and failure isolation.
- **Unified frontend/backend extension**: one plugin package declares both backend APIs and frontend components, menus, and routes — the host renders them with zero code injection.

## Core Principles

	<Card title="Language-agnostic first" icon="puzzle">
		SDKs ship in six languages with feature parity. No single-language lock-in.
	</Card>
	<Card title="Protocol / transport decoupling" icon="arrow-swap">
		One JSON-RPC 2.0 protocol runs over stdio, TCP, HTTP, and future Wasm IPC transports.
	</Card>
	<Card title="Unified lifecycle" icon="circle-check">
		Wasm sandbox, child process, native dynamic library, and remote service — four plugin carriers with one lifecycle.
	</Card>
	<Card title="Deny-by-default security" icon="shield">
		Fine-grained capabilities, tenant grants, user policies, and resource quotas — three layers of authorization.
	</Card>
	<Card title="Multi-tenant as a first-class citizen" icon="group">
		Repository visibility, instance isolation, and quota metering are built in, not bolted on.
	</Card>
	<Card title="Zero-config observability" icon="pulse">
		Plugin-level metrics, logs, and traces without writing instrumentation code.
	</Card>
